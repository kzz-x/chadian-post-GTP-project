# 差点动效 v5

> 用途：作为具体动效提示词的后段辅助提示词。前半段先完成本次具体视觉、场景、构图、动画和节奏设计；只有用户明确同意模板化时，才追加本文件。不要默认套用。

先按照本次提示词前半部分，完成具体的视觉、场景、构图、动画和节奏设计。

**先把作品做好，再把它整理成方便修改和复用的模板。**

---

## 模板化原则

不要把动画写成一次性 Demo。

有复用价值的内容尽量做成：

**场景模板 + 可替换内容 + 可调参数 + 动画预设 + 运镜预设 + 风格预设**

以后应尽量通过：

`换素材 → 调参数 → 换预设 → 改关键帧`

快速生成新的版本，而不是重新写代码。

重复出现的结构、动画、镜头、材质和效果，应抽成可复用模块。

---

## 可编辑结构

主要对象尽量注册为独立图层，使用清晰、有意义的名称和层级。

支持常用操作：

- 选择 / 多选
- 显示隐藏 / 锁定
- 分组 / 父子关系
- 层级调整
- 复制 / 删除
- 位置、缩放、旋转、透明度等基础属性调整

素材、文字、模型、颜色等高频内容不要写死。

内部结构保持清晰，让**人和 AI 都容易继续修改**。

---

## 控件

完成作品后，再做一次 Control Surface Pass：

找出用户之后最可能调整的 **5–8 个核心参数**，放在最前面。

例如：

- 素材 / 模型替换
- 主体位置与大小
- 主色 / 背景
- 动画速度
- 动画强度
- 镜头距离 / 焦段
- 核心视觉效果强度

控件全部中文优先，按功能分类并可折叠。

优先提供“设计意图参数”，不要把大量 Shader、节点、内部变量直接暴露出来。

简单项目不要为了可编辑而过度工程化。

---

## 时间轴与关键帧

动画统一使用一个时间源。

播放、暂停、拖动、逐帧渲染和录制必须对应同一时间状态。

提供接近 AE 的时间轴体验：

- 图层轨道
- 属性轨道
- 关键帧
- 入点 / 出点
- Marker
- FPS / Duration
- 时间缩放
- Auto Key

默认只展开当前选中的图层。

重要可调属性都应可以打关键帧，而不是只能修改固定值。

---

## 动画曲线

不要用大量逐帧硬编码模拟运动。

关键帧支持：

`Linear / Ease In / Ease Out / Ease In Out / Hold / Overshoot / Spring / 自定义 Bézier`

最好提供可视化曲线编辑。

位置、缩放、旋转、透明度、摄像机以及自定义数值属性，都可以使用动画曲线。

复杂运动优先拆成**可编辑关键帧 + 曲线 + 参数**。

---

## Preset 思维

经常重复使用的东西不要只做成参数，要进一步做成预设。

根据项目需要建立：

- 动画预设
- 入场 / 出场预设
- 运镜预设
- 构图预设
- 材质 / 风格预设
- 灯光预设
- 渲染预设

Preset 应支持一键切换，再允许继续微调。

好的模板不是参数越多越好，而是**少量参数 + 高质量预设**就能覆盖大多数修改。

---

## 技术结构

视觉实现方式自由选择最合适的方案：

`HTML / CSS / SVG / Canvas / Three.js / WebGL / Pixi / GSAP / Anime.js / Motion 等`

不要为了统一而强迫所有项目使用同一种 Renderer。

但不同技术路线尽量接入统一的：

`Layer → Property → Timeline → Preset → Render`

动画内容与编辑系统尽量分离。

---

## 预览与输出

保留：

- 播放 / 暂停 / Seek
- Clean Capture
- 画幅 / 分辨率 / FPS
- 预览质量
- 录制 / 导出
- 保存工程 / 重开
- 撤销 / 重做

正式输出优先支持确定性逐帧渲染。

同一个时间点重复渲染，应得到相同结果。

高质量录制与实时预览可以使用不同质量设置。

---

## 最终目标

不要只交付：

**“一个能播放的网页动画。”**

而应该尽量交付：

**“一个已经完成设计，同时拥有图层、控件、时间轴、关键帧、曲线和预设的可复用 Motion Template。”**

用户既可以自己修改，也可以继续让 AI 修改。

但始终遵守：

**作品质量第一，模板化第二，控件数量第三。**

不要为了做编辑器而牺牲视觉质量、性能和开发效率。
