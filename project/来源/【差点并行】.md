# 并行执行协议

用于多个镜头在 B｜设计 或 C｜制作阶段的同步处理。目标是提高吞吐量，但不牺牲阶段边界、统一约束和主Agent验收。

## 何时读取

当满足任一情况时读取：
- 用户一次指定多个镜头进入B，如“展开03、04、06”。
- 用户一次授权多个已确认镜头进入C，如“制作01–03”。
- 用户说“这些镜头一起做/同步做/并行做”。
- 当前宿主具备子Agent、并行任务、分支任务或等价能力。

全文A阶段不因镜头多就自动并行生产。D阶段局部改稿默认不批量并行，除非用户明确指定多镜头同类修改。

## 主Agent职责

主Agent始终是唯一编排者和最终验收者，不能把以下职责丢给子Agent：
- 确定当前阶段、授权范围和停止点
- 解释“继续/剩下的”
- 冻结全局锁定约束
- 判断依赖关系
- 决定哪些任务能并行
- 合并用户新修改
- 最终真实性、连续性、风格和范围检查
- 更新PROJECT_STATE、SHOT_LEDGER和DECISIONS

## 并行前：冻结共享上下文

为当前批次建立简短共享快照，至少包含：

`batch_id｜stage｜authorized_scope｜global_style｜aspect_ratio｜locked_constraints｜truthfulness_rules｜shared_assets｜dependencies`

不要把完整仓库、全部风格、所有历史对话复制给每个子Agent。

每个子Agent只获得：
1. 共享快照
2. 自己的 `shots/Sxx.md`
3. 与当前任务直接相关的reference
4. 与该镜头有关的DECISIONS条目
5. 明确的输出路径和停止点

例：S03 CGI设计只需 `visual.md + clips.md + styles/016.md + S03.md`；不需要封面、图表、其他17张风格卡。

## 先建依赖图

可以并行：
- S03、S04、S05互不依赖的镜头设计
- 多镜头真实素材搜索
- 多个独立元素资产
- 已确认方案后的多个独立CGI锚点
- 已确认的多个独立HTML/动效镜头

必须顺序：
- 同一镜头“先真实产品参考 → 再CGI”
- “先锚点通过 → 再视频”
- “先核数据 → 再正式图表”
- “先母版定稿 → 再批量套版”
- 后一任务明确依赖前一任务产物

依赖关系不清楚时宁可同镜头内顺序执行，也不要为了并行让后续任务基于假设启动。

## B阶段并行

多个独立镜头可同步完成各自设计卡和Prompt，但每个子Agent必须：
- 只停在B
- 不生成、不编码
- 不修改其他镜头
- 写回自己的 `shots/Sxx.md`
- 标明待核项和依赖

主Agent收回结果后做一次批次级检查：
- 风格是否无意漂移
- 同类信息是否重复构图
- 全片节奏是否连续
- 是否有镜头越阶段
- Prompt是否完整
- 锁定项是否一致

## C阶段并行

只有满足下列条件的镜头才直接进入并行C：
- 在authorized_scope内
- 已完成需要的B设计并满足确认要求，或用户明确“直接做/无需确认”
- 不依赖另一个尚未完成的本批任务
- 所需真实参考/数据已具备或可在自身任务中先完成

每个子Agent把实际成果和状态写入自己的镜头文件/输出目录。未实际完成不能标完成。

## 子Agent完成后的强制汇总

主Agent必须重新读取子任务结果，不能只根据“任务完成”通知判断质量。

至少检查：
1. 内容与事实
2. 已锁定约束
3. 风格/材质/文字策略
4. 连续性
5. 文件与实际产物状态
6. 未测/失败项

之后统一更新：
- `SHOT_LEDGER.md`
- `PROJECT_STATE.md`
- 必要时 `DECISIONS.md`

## 失败与重试

一个子任务失败：
- 不自动让全批次重做
- 只重试该镜头或降级该镜头
- 有新方法才重试
- 其他镜头可继续完成

共享规则本身错误时，暂停受影响的子任务，由主Agent更新共享快照再继续。

## 无子Agent能力

如果宿主不支持子Agent/并行任务：
- 按同一批次逐镜头顺序执行
- 保持同样的文件、状态和验收契约
- 可以说明“当前环境顺序执行”
- 不能声称已并行
