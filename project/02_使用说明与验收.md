# 差点后期｜GPT Project 使用说明与验收

版本：v3.0 · 2026-09-06

## 1. 安装到 GPT Project

1. 将 `project/01_项目指令.md` 正文作为 Project Instructions。
2. 上传 `project/来源/` 中需要的来源文件。
3. 风格优先上传/使用 `project/来源/风格/000.md`～`017.md` 的拆分文件；旧 `【差点风格】.md` 仅保留兼容，不作为正常运行入口。
4. `project/模板/` 是文件化工作区模板；如果当前 ChatGPT/Agent 支持创建文件或Artifact，运行时复制这些结构建立项目状态。
5. README/CHANGELOG/VERSION/MAINTENANCE/archives 不作为日常创作来源。

## 2. v3 的渐进读取

新全文：先读【差点后期】，只做A分析并停止。

设计/制作时按需读取：
- 构图/不好看 → 【差点视觉】
- 真实素材 → 【差点素材】
- 独立PNG/零件 → 【差点元素】
- CGI/AI镜头 → 【差点片段】
- 参数/图表/HTML/AE → 【差点动效】
- 封面 → 【差点封面】
- 组件/字体/库 → 【差点资产】
- 验收 → 【差点质检】
- 多镜头同步 → 【差点并行】
- 独立文件交付 → 【差点交付】
- 长对话/剩余镜头 → 【差点状态】
- 指定风格 → 只读 `来源/风格/<编号>.md`

不要一次性把全部来源和18张风格卡加载进当前任务。

## 3. 长项目工作区

推荐运行时文件：

```text
00_全文分析.md
01_镜头总表.md
PROJECT_STATE.md
SHOT_LEDGER.md
DECISIONS.md
shots/S01.md ...
outputs/S01/ ...
```

A阶段先建立全部镜头文件骨架；B/C/D持续更新同一镜头文件。聊天只保留当前摘要和文件入口。

“开始做剩下的”必须读取 `PROJECT_STATE + SHOT_LEDGER + DECISIONS` 计算剩余集合，不靠聊天记忆。

## 4. 子Agent并行

只有B/C阶段、多个独立镜头且同一批次已获授权时使用。

主Agent先冻结：全局风格、画幅、锁定项、真实性、共享资产和依赖。

每个子Agent只得到：自己的镜头文件 + 必要来源 + 相关决策。

依赖链如“真实参考→CGI”“锚点→视频”“核数据→图表”保持顺序。子Agent完成后由主Agent重新读取结果并统一验收，再更新总账。

宿主没有子Agent时顺序执行，不声称并行。

## 5. 文件化交付验收

支持文件工具时应检查：
- A后是否有全文、镜头总表、状态文件和每镜Sxx文件
- B是否更新当前镜头并保存完整Prompt
- C是否记录实际成果/路径/来源/检查，而非Prompt冒充成品
- D是否记录保留项/修改项/新决策
- 本轮关键文件是否被暴露为可点击/可预览/可下载的Artifact（具体UI位置不强制）

不支持文件工具时必须明确降级为聊天结构，不能称已创建文件。

## 6. 行为回归用例

v3 当前定义15项行为eval，重点包括：
1. 全文只到A
2. 展开03只到B
3. 确认不制作
4. 真实素材不AI补缺
5. 封面双版Prompt且无最终大标题
6. 不好看先诊断
7. 只改颜色不漂移
8. 粗动效先设计锚点/视频Prompt
9. 可编辑动效不能缩水
10. 继续按state解释
11. 多镜头B可并行但不越C
12. 多镜头C可并行并由主Agent统一验收
13. “做剩下的”读取总账
14. 15镜全文建立独立镜头文件
15. 无子Agent环境顺序降级

这些用例已经写入 `skill/evals/evals.json`，但尚未真实跑完 with-skill vs baseline；因此不能声称全部通过。
