# AI 动效开发核心经验

> 用于 AI 在 Three.js / WebGL / Blender / AE / 互动三维科普 / Vibemotion 等动效开发前快速读取。
> 只保留跨项目反复成立的高价值经验；目标是减少返工，不限制创作发挥。

## 0. 维护原则

- **压缩式更新，不做追加式堆积。** 新经验优先合并、替换、压缩已有规则；只有真正通用且反复验证的新原则才新增。
- **项目细节不进入本文件。** 参数、具体技术结构、单次 bug、案例过程留在项目复盘里。
- **原则说明“什么最重要”，不规定唯一实现。** AI 可以自由选择技术路线，只要最终结果满足核心目标与验收。

## 1. 核心原则

1. **结构先于视觉**：先确认部件关系、尺度、连接、层级、数据/能量路径与知识逻辑，再做材质、灯光和装饰。
2. **空间运动先于透明度**：转场优先通过推进、剖开、重排、翻转、拆解、聚合、尺度变化等空间过程完成；淡入淡出只用于必要收尾。
3. **先设计路径，再调缓动**：穿模、跳变、突兀先检查旋转中心、扫掠空间、相机通道和安全距离；Easing 只优化节奏。
4. **动画共享统一时间状态**：同一个时间 `t` 应得到同一组 Camera、模型、特效和标注状态，确保暂停、跳转、拖动、反向和录制一致。
5. **宏观与微观保持对象连续性**：尽量追踪同一个对象、区域或结构关系，不用另一套模型突然替换再靠透明度掩盖。
6. **材质质感不能依赖后期掩盖**：几何、灯光、环境反射、材质分工和接触关系先成立，再加 Bloom、DOF、体积光、滤镜。
7. **标注和特效也是动画的一部分**：有明确出入场并跟随真实对象；路径、强度、脉冲等状态与模型和镜头同步。
8. **模板优先数据驱动和可复用**：稳定身份、清晰模块边界、共享状态；避免为了单个镜头把结构、路径和参数写死。
9. **先做代表样片，再扩展功能**：先跑通一个代表镜头的结构、动画、转场、材质、标注和录制，再批量加技术类型、预设和控件。
10. **验收看全过程，不看最好看的截图**：检查关键中段、快速切换、暂停后继续、反向、拖时间线、循环首尾、隐藏恢复、标注开关和最终导出文件。

## 2. 推荐开发顺序

**结构关系 → 代表镜头 → 宏微观连续转场 → 安全运动路径 → 统一时间状态 → 标注/特效 → 材质灯光 → 控件 → 录制 → 回归测试 → 扩展功能**

不要反过来先堆 UI、控件、Bloom、粒子和大量预设，再补救底层结构与运动问题。

## 3. 更新规则

每次项目复盘后，只问：
1. 是否跨项目成立？
2. 能否合并/替换已有原则，而不是新增？
3. 加进去是否明显减少返工，同时不过度限制 AI 发挥？

只有 **通用、反复验证、能显著减少返工** 的经验进入本文件。
