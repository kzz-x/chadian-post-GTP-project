# 差点后期

把复杂后期任务拆成可审阅、可决定、可修改、可复用的阶段。不要一次性把整片全部生产，也不要把项目进度只存在聊天记忆里。

## 核心边界

1. 全文输入不等于授权制作。新全文先完成A全文分析，然后停止。
2. B设计与C制作分开。`展开03/设计03/设计封面`只设计；`制作03/找03素材/生成这版底图`才执行。
3. 同一轮只处理用户授权范围。`确认/可以/方案A`只锁定，不自动制作；`继续`按当前阶段解释。
4. 工具结果必须真实：没搜到不称找到，没下载不称下载，没生成不称成品，没运行不称实测通过，没读视频不编动作/时间码。
5. 已确认的画幅、主体身份、标题区、字体、媒介、构图、文字策略和未点名要改的部分持续锁定，直到用户明确撤销。
6. 使用最短有效能力链。不要因为“可能有用”就加载全部references。
7. 对话不是项目状态的唯一来源。平台支持文件时，使用项目状态文件和镜头文件保存进度；长对话、上下文压缩或重新进入任务时优先恢复这些文件。
8. 多个互相独立的镜头在B或C阶段可并行处理；有子Agent/并行任务能力时按 `references/parallel-execution.md` 调度，没有时顺序执行同一批次并保持相同交付契约。
9. **Search First**：进入具体视觉、动效、封面、CGI、AI片段或复杂元素的 B/C 阶段时，先按 `references/search-first.md` 判断 Truth / Reference / Asset 三种独立 Gate。成熟语义资产、Logo、Animated Icon、3D Model、HDRI/Texture 等命中 Asset First 时必须先搜现成资产；确认无合适结果后才允许自制。A 全文分析仍不外搜。
10. **AE Handoff**：`差点后期` 只负责判断镜头是否适合 AE、锁定表达目标/构图/参考/素材与阶段状态；一旦用户要求 AE 制作方案、工程搭建、MCP/JSX、关键帧/表达式、AE修改/调试/验收，必须转读 `kzz-x/XPIN-AE-SKILL`，由其中 `AGENTS.md` 路由 Mini / Full。不要用 `references/motion.md` 代替 AE Skill。

## 运行状态

持续维护：`stage`、`current_object`、`design_version`、`authorized_scope`、`locked_constraints`、`pending_verification`、`shot_index`、`active_batch`、`completed_shots`、`remaining_shots`。

处理新消息前：
1. 若存在 `PROJECT_STATE.md` / `SHOT_LEDGER.md` / `DECISIONS.md`，先从这些文件恢复项目状态。
2. 再结合最近对话中的最新明确用户要求。
3. 最新明确用户要求优先，只更新冲突字段；其他锁定项继续有效。
4. 不依赖几十轮前的模糊记忆替代当前状态。

用户说“剩下的/剩余镜头/继续做剩下的”时，必须按 `references/project-state.md` 读取总账计算集合，不能凭印象猜。

| 多镜头批量设计/制作、要求同步/并行、平台有子Agent能力 | `references/parallel-execution.md` |

不要预加载整个 `references/`。一个镜头使用最短有效文件组；只有任务真正跨媒介时才组合多个文件。已完整读入且仍在当前上下文中可准确使用的reference不需机械重复读取。

## 文件化项目交付

当宿主支持创建、更新或暴露文件/Artifact时，使用 `references/artifact-output.md`：

- A完成后建立 `00_全文分析.md`、`01_镜头总表.md`、`PROJECT_STATE.md`、`SHOT_LEDGER.md`、`DECISIONS.md`，并为每个镜头建立稳定的 `shots/Sxx.md`。
- B/C/D只更新当前对象对应文件和总账，不把完整项目重新塞回聊天。
- 聊天正文只保留当前阶段摘要和最关键操作入口；当前变更文件应尽量作为可点击/可预览/可下载Artifact暴露给用户。
- 文件在界面中的具体位置由宿主决定；不要声称能强制显示在侧栏。
- 宿主无文件能力时，退化为结构化聊天输出并保留状态锚点，不能假称已创建文件。

## 并行镜头

只在B/C阶段、多个镜头互相独立且用户授权同一批次时考虑并行。

有子Agent/并行任务能力：
1. 主Agent冻结全局约束与本批范围。
2. 为每个子Agent只提供该镜头卡 + 必要references + 相关决策，不给整个仓库。
3. 依赖链必须顺序执行；例如“先找真实参考→再按参考做CGI”不能拆成同时开始。
4. 子Agent结果先写回各自 `shots/Sxx.md`/输出目录。
5. 主Agent重新读取结果，统一做真实性、风格、连续性和范围检查，再更新总账。

无子Agent能力：按同样批次顺序执行，不声称并行。

详细规则见 `references/parallel-execution.md`。

## 人工标注

识别 `（素材）` `（元素）` `（片段）` `（动效）` `（CGI）` `【风格：000–017】` `【只找真实素材】`。

- 段后标注绑定前一视觉意群；段前独立标注绑定下一视觉意群。
- 只有明确“全文/全片”或文首全局设置才全局继承。
- 标注决定媒介和约束，不自动授权跨阶段制作。
- `【只找真实素材】`范围禁止生成补缺。

## SHOT投入

- `SHOT-B`：过渡/一般事实；一个有效素材、模板或字幕方案，必要时一个替补。
- `SHOT-A`：关键对比/因果/结构/重要数据；一套定制解释构图和一个主动作。
- `SHOT-S`：开场、重大转折、结论记忆点、难替代概念；一个强主视觉，先静帧再运动。

整片不全部S。一个镜头默认一个主视觉、一个主动作。

## 画幅

普通视觉、AI镜头、动效默认16:9（1920×1080），同时兼容约1183×1080；核心信息优先放中央约62%宽区域。横向关系不适合裁切时做独立窄版重排。

封面默认16:9 + 3:4独立构图：横版标题兼容区在中下部，竖版在下半部居中展开，底部留余量；背景保持完整，不用机械裁切冒充竖版。

## A｜全文分析

入口：用户粘贴整篇文案，或A尚未完成时说“继续”。新全文先读取 `references/post-details.md`；宿主支持文件时同时读取 `references/artifact-output.md` 与 `references/project-state.md`。

只做：全文理解、视觉意群拆分、S01…完整索引、媒介/SHOT/风格初选、待核项。不要外搜、下载、生图、生视频、写HTML/AE/工程、自动做封面或增加新数据。

固定顺序：
1. 全文理解：一句话结论 + 结构/转折/节奏
2. 全篇镜头总览
3. 逐镜头八项卡：原文；表达目标/关系；主视觉；构图；动作；媒介/能力/风格；SHOT/估时/画幅；待核/待定
4. 待核验/待决定项
5. 写入/更新阶段文件和镜头文件（若宿主支持）
6. 停止

长文可每轮展开3–5张详细卡，但必须先给全篇镜头索引；文件化环境中应先建立全部 `shots/Sxx.md` 的A阶段骨架，避免用户后续反复向上翻聊天。

## B｜指定对象设计

入口：`展开03` `设计03` `下一镜` `设计封面` `只要提示词`，以及用户一次指定多个镜头进入设计等。

只设计当前对象或明确批次。读取当前能力reference；需要视觉关系时读`visual.md`；指定风格只读对应风格卡。不要为了“全面”把其他能力一起读入。

若当前对象是新视觉、新动效、封面、CGI、复杂产品/结构、类生物动作、机械/物理运动，或包含图标 / Logo / Lottie / 3D / HDRI / Texture / 成熟组件等可复用对象，先按 `references/search-first.md` 做 Search Preflight。命中 Reference First 时主动整理图片、视频、GIF/Lottie、成熟动效；命中 Asset First 时主动检索现成资产并形成 Asset Manifest。**B 阶段主动搜索属于设计，不等于授权进入 C 制作。**

如果本镜头最终路线明确为 AE：本 Skill 可完成镜头层面的表达目标、构图、参考、素材和节奏意图；当用户进一步要求“AE怎么做 / AE制作方案 / 直接做AE / JSX / MCP / 改AE工程”时，立即转读 `kzz-x/XPIN-AE-SKILL/AGENTS.md`。交接时把当前镜头卡、已锁定约束、参考和素材需求作为输入，不从零重新设计。

开头给：`依据：实际读取的文件/章节；关键约束：3–5条；本轮交付：…`

凡后续涉及生成，B必须交完整、可复制Prompt；不能只写“用016/更高级/科技感”。单镜头交付完停止；多镜头批次可按 `parallel-execution.md` 同步设计，但不得越到C。

若宿主支持文件，B完成后更新各自 `shots/Sxx.md`、`SHOT_LEDGER.md`、`PROJECT_STATE.md`，并在聊天中暴露本轮变化文件。

## C｜指定制作

入口：`制作03` `找03素材` `核验这条数据` `生成这版底图` `按方案改图` `直接做`，以及用户明确授权多个镜头/剩余镜头进入制作。

只执行`authorized_scope`。有已确认方案就按该版执行。无方案但用户明确“直接做/无需确认”时，可合并B+C，但必须先公开简短方案和完整Prompt/技术方案，再调用工具。

进入制作前复核 Search First 结果：准确产品/结构、复杂机械、类生物运动、物理现象和明显 Motion 任务不要在缺乏依据时凭空补细节；命中 Asset First 的对象若仍为 `UNSEARCHED`，先补搜，不得因为自己画更快就跳过。能直接复用官方素材、SVG、Lottie、Animated Icon、视频、3D、HDRI/Texture 或模板时优先复用；确无合适资产再自制或使用明确标注的可替换占位。

若 `authorized_scope` 是 AE 制作/修改，不在本仓继续执行 `references/motion.md` 的工程流程；转读 `kzz-x/XPIN-AE-SKILL/AGENTS.md`，并把本仓已确认的镜头设计与 Reference Brief 作为 AE Skill 的上游约束。

多个已设计且互相独立的镜头可以并行制作；读取 `references/parallel-execution.md`。所有子任务完成后由主Agent统一验收并更新项目状态。

用户说“开始做剩下的”时先读取项目状态文件，计算剩余集合：
- 若当前语境是C制作，优先选择“已设计/已确认但C未完成”的镜头。
- 尚未完成B的镜头不能被“剩下的”自动越过B；除非用户同时明确“剩下的直接做/不用确认”。
- 计算出的本批清单要在执行前明确列出。

交付分区：实际成果 → Prompt/配置/来源 → 实际检查 → 缺口/未测。不要顺手制作未授权镜头。

## D｜验收与修改

入口：`检查03` `不好看` `一眼AI` `只改颜色` `按方案改图`。

只有模糊“不好看”时，先给最多3个高影响问题：`具体问题 → 影响 → 可执行改法`，并列保留项/允许修改/禁止修改，然后停止。明确编辑命令时只改指定范围。需要换媒介、核心主体或推翻已确认方向，先说明理由并等待授权。

若产生新的长期锁定决策，写入 `DECISIONS.md`；完成修改后更新对应镜头文件、总账和项目状态。

## 短指令

- `继续`：先恢复项目状态；A未完→续A；A已完→第一个未设计镜头B；B未完→补B；B已齐但未授权→报告就绪；已授权C批次→只续该批次。
- `确认/可以/方案A`：锁定，不进入C；更新决策/镜头状态。
- `下一镜`：下一个镜头B，不生成。
- `制作03/按这个生成`：当前对象进入C；若缺设计先补B，除非明确直接做。
- `找03素材/核验数据`：只执行指定搜索/核验。
- `不好看`：D诊断，不自动重生。
- `只改XX`：只改XX，其余锁定。
- `只要提示词`：只交Prompt，不生成。
- `开始做剩下的/剩下的继续做`：读取总账计算剩余集合，不凭聊天印象；按当前阶段边界执行。

## 输出协议

第一行：`当前阶段｜当前对象/镜头｜版本｜本轮交付`

正文只写当前阶段需要的内容。信源、镜头卡、Prompt、工程结果分区，不混成工作日志。

若宿主支持文件：
- 优先把完整阶段成果写入文件。
- 聊天只给摘要、当前文件入口、风险/待决定和下一步。
- 不重复粘贴已经存在于文件中的长内容。

结尾：`本轮已完成：…｜已锁定：…｜待核/待决定：…｜下一步：<一条最具体指令>`
